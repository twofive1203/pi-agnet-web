## Styles

Global CSS lives in `app/globals.css`. New or migrated UI must consume semantic roles rather than palette values or component-specific colors:

```text
Surface:   --surface-app --surface-panel --surface-raised --surface-subtle
           --surface-hover --surface-selected --surface-overlay
Border:    --border-default --border-subtle --border-strong --border-focus
Text:      --text-primary --text-secondary --text-tertiary --text-inverse --text-accent
Accent:    --accent-primary --accent-hover --accent-soft --accent-border
Status:    --status-{success|warning|danger|info}-{foreground|soft|border}
Shape:     --radius-* --control-height-*
Elevation: --shadow-sm --shadow-panel --shadow-popover
Focus:     --focus-ring-color --focus-ring-width --focus-ring-offset
Motion:    --motion-duration-* --motion-ease-*
```

Theme selectors set only `--palette-*` values; the root semantic layer maps those values to component roles. Existing variables remain compatibility aliases during gradual migration: `--bg*` → `--surface-*`, `--border`/`--line*` → `--border-*`, `--text`/`--text-muted`/`--text-dim` and `--text-2`/`--text-3` → semantic text roles, `--accent` → `--accent-primary`, `--ok`/`--warn`/`--danger`/`--info` → semantic status foregrounds, and `--radius*` → semantic radius roles. Do not remove an alias until repository search shows that it has no callers. Tailwind `--color-*` aliases resolve through the same semantic layer.

`lib/theme.ts` is the single theme registry. Each entry owns its resolved mode, skin flag, i18n label key, and three-color Picker preview; `ThemePicker`, `useTheme`, and the pre-hydration script in `app/layout.tsx` derive their options/mode/skin behavior from this metadata. The appearance system stores the selected preference under `localStorage["pi-theme"]`, toggles `dark` on `document.documentElement` for binary editor/renderer compatibility, and sets `data-theme-skin` only for curated skins. Invalid stored values fall back to `system`, and applying a core theme clears stale skin data before first paint. The opt-in MetaCubeXD family (`twilight`, `night`, `daisy-dark`, and `dracula`) retains its existing scoped material effects; Night, Daisy Dark, and Dracula preserve the DaisyUI 5.7.0 base/content/primary relationships without adding DaisyUI as a dependency.

Workbench skin extras live in `lib/theme-skin.ts` and stack on top of the curated preference. Background mode is `none` | `image` | `gradient` (`localStorage["pi-theme-bg-mode"]`), with optional local wallpaper data-URL (`pi-theme-wallpaper`), preset gradient id (`pi-theme-gradient`), and independent 0–100 levels for glass (`pi-theme-glass`), frost clarity (`pi-theme-frost-clarity`, scales the glass-derived panel blur down to zero), background blur (`pi-theme-bg-blur`), and vignette (`pi-theme-vignette`). The boot script restores the full stack before paint via `buildWorkbenchSkinBootFragment()`. CSS uses a fixed `body::before` blur layer and `body::after` scrim/vignette so text stays sharp; tokens are `--skin-bg-image` / `--skin-wallpaper-image`, `--skin-glass`, `--skin-panel-alpha`, `--skin-panel-blur` (alias `--skin-blur`), `--skin-bg-blur`, `--skin-vignette`, and `--skin-scrim`, plus `data-wallpaper=image|gradient` and `data-glass`. Wallpaper never leaves the browser, remote URLs are rejected, and high-frequency reading surfaces keep solid semantic fills. First background enable defaults glass/blur/vignette to moderate values when still off; Reset clears extras without changing the curated theme. `prefers-reduced-motion` disables background blur.

Run `npm run test:ui-theme` whenever changing the theme registry, boot script, Picker metadata, semantic/layer Token names, compatibility aliases, stable shared UI classes, responsive breakpoints, Portal focus behavior, coarse-pointer/safe-area rules, or reduced-motion behavior. The smoke checks synchronization and static contracts; it does not replace the representative-theme browser matrix in `docs/operations/ui-visual-validation.md`.

Chat visuals use three scoped class families in `app/globals.css`: `message-*` for message/action/Thinking/tool hierarchy, `chat-input-*` for the Composer and viewport-bound menus, and `extension-*` for status/widget/todo/toast surfaces. Assistant prose must remain an open reading surface rather than receiving the same bordered card as nested tools. Static hover/focus/disabled/status visuals belong in these classes; inline styles are limited to runtime coordinates, measured heights, drag positions, progress widths, and domain visualization values. Message actions must remain reachable through `focus-within` and coarse-pointer rules, not hover alone.

Inspector content uses shared `inspector-*` primitives for sections, stat cards, list rows, badges, scrolling, and empty/loading/error states. Preview adds the quieter `preview-tab-*` level; Git/Diff use `git-*`, `commit-graph-*`, and `diff-*`; SnFlow and Agents use `workflow-*` and `subagent-*`. Generic surfaces, borders, focus, and statuses must use semantic Tokens, while commit lanes and added/deleted diff data retain domain color meaning. Narrow behavior follows container width—not only viewport width—so the 300px Inspector stacks SnFlow list/detail and Git history/detail without page-level horizontal overflow. Inline values remain valid for graph geometry, drag positions, and recursive indentation.

Settings surfaces use `components/ui/SettingsPrimitives.tsx` plus `settings-*` classes for ordinary fields, toggles, buttons, badges, notices, action rows, surfaces, segmented tabs, and state views. Use `SettingsField` for associated label/description/error content, `SettingsBadge` for compact textual classification, `SettingsNotice` for actionable status or risk, `SettingsActionRow` for wrapping header/footer actions, `SettingsSurface` for nested groups, `SettingsTabs`/`SettingsTab` for compact local views, and `SettingsButton` variants for action hierarchy. The primitives are presentation-only: owning components retain loading, validation, dirty, save, secret, conflict, and API behavior. MCP, Agents, Models, Extensions, and Skills keep their existing independent data/save boundaries. Blocking dialogs and simple modals use one `.pi-modal-overlay` / `.pi-modal-panel` / header/body/footer shell; panel size and runtime content remain component-specific. Dense configuration UIs share `resource-*`, `models-*`, and `usage-*` layout classes; generic surface, input, button, focus, and status appearance must stay in semantic Settings/resource primitives, while quota pies and provider logos may retain domain visualization colors. At ≤640px Settings navigation scrolls horizontally, resource/model split navigation stacks above detail, wide grids become one column, and shared modal panels fill the viewport.

Desktop split sizing uses shared `.panel-resize-handle` styles plus `--right-panel-width` on `.app-shell-root`. Inline resize applies at `min-width: 960px`, with a 300px Sidebar, 360px minimum Chat target, and 300px minimum / 380px baseline Inspector. The shell gutter scales from 0px at 960px to 12px on wider viewports; `AppShell` subtracts the same two paddings and two gaps when clamping a stored Inspector width. Between `641px` and `959px` the Inspector is an inset overlay drawer with no resize handle. At `max-width: 640px`, Sidebar and Inspector are full-height overlay drawers, all resize handles are hidden, expanded Explorer equal-shares the remaining Sidebar height, and Sidebar/Inspector/Composer/Toast/Todo surfaces honor safe-area insets. The Inspector starts collapsed on first load in every layout (`rightPanelOpen` defaults to `false`); users reopen the last active tab through the focused header's Inspector trigger, and narrow layouts also force it closed on breakpoint transitions. The retired 860px media query must not be reintroduced as a layout state; `npm run test:ui-theme` statically checks these breakpoint contracts.

Shared keyboard behavior is part of the visual contract. Theme Picker and Inspector tabs use roving focus with arrow keys plus Home/End; Composer Model/Thinking/Tools portals expose listbox/option semantics, move focus into the active option, close on outside focus, and return focus to the trigger on Escape/selection. Application and extension dialogs trap focus, ignore disabled controls, and restore the previously focused element. At coarse-pointer breakpoints, high-frequency top-bar, Composer, Inspector, Settings, and dialog actions receive enlarged targets. The final global `prefers-reduced-motion` gate suppresses decorative transitions/animations while status text, icons, and shapes remain meaningful.

Portal stacking must use the `--z-*` layer Tokens in `app/globals.css`, not new component-local large z-index values. The order is workbench card → drawer backdrop → Sidebar/Inspector drawers → Automation drawer → top portals → terminal fullscreen → context menu → dialogs. Keep runtime coordinates and measured sizes inline, but keep surface, focus, motion, touch-target, and layer behavior in stable semantic classes.

## Internationalization (i18n)

- **Supported locales**: `zh` (default when browser is Chinese), `en`.
- **Provider**: `components/I18nProvider.tsx` wraps the app in `app/page.tsx`.
- **Catalogs**: `lib/i18n/messages/*` nested dictionaries; lookup via dotted keys such as `sidebar.archiveAllSessions`.
- **API**: `const { locale, setLocale, t } = useI18n()`; `t("key", { name })` interpolates `{name}` placeholders.
- **Persistence**: `localStorage["pi-locale"]`; boot script in `app/layout.tsx` sets `document.documentElement.lang` early to reduce flash.
- **Switcher**: top-bar `EN`/`中` button in `AppShell`, and Settings → Language section.
- **Coverage status**: shell/chat/sidebar/git/terminal/diff and shared chrome strings are wired. Large settings/models panels still contain mixed hard-coded Chinese/English copy and should continue migrating onto `settings.*` / `panels.*` keys.
