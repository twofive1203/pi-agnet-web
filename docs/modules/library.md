# Library Module Map

Shared logic lives under `lib/`. Prefer adding behavior here when it is used by multiple API routes, hooks, or components.

| File | Purpose |
| --- | --- |
| `lib/rpc-manager.ts` | `AgentSessionWrapper`, global registry, `startRpcSession()`, cwd-scoped session cleanup, lifecycle handling, settlement-based idle teardown (no destroy while tools/Subagents/blocking UI are active; SSE listener count does not own lifetime), `getTaskObservation()` / task-observer wiring on the raw event boundary, `getRpcRuntimeStats()` for ops health, and prompt/steer/follow-up attachment routing through the configured Vision resolver when the active model lacks image input. Interactive loaders always attach the empty-completed retry normalizer extension. |
| `lib/empty-completed-retry.ts` | Provider-targeted `message_end` normalizer: empty post-tool `completed` assistant responses become retryable errors when the provider sets `emptyCompletedRetry: true` in `models.json`. |
| `lib/model-primary-candidates.ts` | Client-safe favorite-key, legacy `models.json` flag parsing, picker grouping, and default short-list projection helpers (favorites first; full list when none marked). |
| `lib/model-primary-candidates-server.ts` | Server-only cached reader for legacy `models.json` `primaryCandidate` flags, retained as the first-write migration source. Keep out of client bundles. |
| `lib/model-favorites.ts` | Versioned user-global WebUI model-favorites sidecar: strict provider/model normalization, legacy first-write migration, serialized updates, and atomic persistence under `~/.pi/agent/model-favorites.json`. It is independent of Pi model execution configuration. |
| `lib/agent-retry-errors.ts` | Shared empty-completed retry error text so the normalizer and UI stay aligned. |
| `lib/agent-lifecycle.ts` | Pure mapping from Pi lifecycle events to WebUI settle/keep-running directives. |
| `lib/chat-prompt-lifecycle.ts` | Pure prompt-level chat state machine and in-process harness (throttler → apply) for browser-free integration smokes: `agentRunning`/`phase`/retry/failure/stream settle on `agent_settled`/`prompt_error`, keep busy across `agent_end` retry gaps, and flush pending text before tool/lifecycle barriers. Documents the contract mirrored by `hooks/useAgentSession.ts`. |
| `lib/chat-provider-errors.ts` | Classify provider/SDK failure text into auth/quota/network/model_not_found/empty_response categories with stable `ERROR_CODES`, localized titles/actions, and `buildChatAgentFailure()` used by the chat failure card. |
| `lib/chat-send-readiness.ts` | Pre-send composer gate: block ordinary sends when workspace/models/selection are missing and expose Models fix entry reasons. |
| `lib/chat-follow-up-queue.ts` | Client-safe follow-up queue snapshot normalization, duplicate-aware removal detection, and user-message text correlation used to keep queued items outside the persisted chat timeline until delivery starts. |
| `lib/pi-session-lifecycle.ts` | Shared AgentSession disposal helper: drain active agent/compaction work, await extension `session_shutdown`, then SDK `dispose`/ctx invalidation. Prevents stale-extension-ctx races during session replace/reload/teardown. |
| `lib/session-reader.ts` | Parse `.jsonl` session files, resolve session paths, prune/delete sessions for removed WorkTree cwd paths, read model/default config. Sidebar browsing uses `listProjectSummaries()` and `listRecentSessionsForCwd(cwd, { limit, before, beforePath })` (mtime/filename candidate selection, bounded page parse, optional parent-closure ancestors, `total`/`hasMore`/`nextBefore` cursors). Project/candidate collection prefers `lib/session-index.ts` and falls back to direct disk scans. Archived sidebar pages use `listArchivedSessionsForCwd(cwd, options)` the same way; no-options call remains a full cwd list. `listAllSessions()` / `listAllArchivedSessions()` stay full-scan for Usage and bulk consumers. `resolveSessionPath` prefers filename scan before full list. `resolveLiveOrDiskSessionManager()` reuses a matching live parsed manager. `buildSessionContext()` remains the compaction-aware LLM/runtime projection and is not the chat transcript. Archive helpers move/restore the parent JSONL together with its subagent companion directory through `lib/session-artifacts.ts` and invalidate the session index. |
| `lib/session-transcript.ts` | Current-branch display transcript: project raw messages / custom_message / compaction and branch-summary markers, turn-aware entryId pagination, real `messageCount` / `firstMessage`, and cursor error mapping. Independent from Pi `buildSessionContext()`. |
| `lib/session-transcript-client.ts` | Client-safe transcript page replace/prepend/tail-merge, stale session/leaf/sequence checks, and prepend scroll-anchor restore. Dedupes by entryId only. |
| `lib/session-reader-header.ts` | Bounded first-line session header peek and filename id extraction shared by reader and index (avoids circular imports). Requires session `type`, string `id`, and string `cwd` before treating a header as valid. |
| `lib/session-index.ts` | Rebuildable WebUI session/project index persisted at `~/.pi/agent/pi-web-session-index.json` (versioned; v2). Fingerprints entries by `path + mtimeMs + size` (+ archived flag), reuses unchanged entries, and stores searchable browse summaries (`name`, `firstMessage`, `messageCount`) beside header fields. Isolates malformed/unreadable files (including typed-malformed non-string `cwd`) per file so one bad JSONL cannot abort refresh or hide valid entries, atomically writes via temp+rename, and serializes refresh/write in-process via `globalThis`. Exposes `getSessionIndexCwdRoots()` for allowed-roots and usage candidate acceleration. Index is an acceleration layer only — disk JSONL remains the source of truth; cache write failures never block browse/search. |
| `lib/session-search-summary.ts` | SDK-free bounded JSONL scan that extracts latest `session_info.name`, first user-message preview, and messageCount for index rebuilds. |
| `lib/session-search.ts` | Workspace-scoped session search over index summaries (`name` + `firstMessage` only). Hard-capped results, cwd isolation via real `header.cwd`, optional archived inclusion, newest-first flat projection with best-effort WorkTree metadata. |
| `lib/session-search-client.ts` | Client-safe pure helpers for search response application (abort/cwd/seq isolation). |
| `lib/session-reader-constants.ts` | Client-safe constants shared with session-reader/browser (`RECENT_SESSIONS_LIMIT`, `ARCHIVED_SESSIONS_LIMIT`, `PARENT_CLOSURE_LIMIT`, session search debounce/min-query/limit caps). |
| `lib/session-billing-stats.ts` | Aggregate parent-session lifetime billed usage with Pi CLI semantics: all assistant/tool-result usage plus compaction and branch-summary calls, including entries outside the active context. |
| `lib/sidebar-session-tree.ts` | Pure sidebar fork-tree builder (`buildSessionTree`) and session-page merge helper used by the session browser. |
| `lib/types.ts` | Shared TypeScript types for messages, sessions, Git status/graph/commit/diff wire payloads, API payloads, `SessionContextState`, and `SessionTranscriptPage`. |
| `lib/pi-types.ts` | `AgentSessionLike` wrapper interface expected by hooks/components, including pending/follow-up queue snapshot access used by live state projection. |
| `lib/normalize.ts` | Normalize pi tool-call fields to web UI shape. |
| `lib/subagent-runs.ts` | Shared Subagent summary projection types and logic. Expands single/parallel/chain execution calls and rebuilds completed/failed rows from persisted tool calls/results, with result text bounded to an 8k preview plus truncation metadata. Centralizes legacy `trellis_subagent` compatibility for live SSE and persisted replay. |
| `lib/subagent-progress.ts` | Pure live-progress helpers for the Subagent panel: normalize progress snapshots, match snapshots to local runs (index-first), derive urgent flush, map control activity, and serialize a lightweight flush key for AppShell. Used by `hooks/useAgentSession.ts` and `scripts/smoke-subagent-progress.mjs`; no React dependency. |
| `lib/parse-subagent-children.ts` | Async bounded native-subagent detail reader. Reads at most 1 MiB using head/tail windows, limits parsed entries/direct children/output, returns an mtime/size fingerprint and truncation metadata, and never recursively scans descendants. |
| `lib/subagent-store.ts` | AppShell-scoped external store with separate stable snapshots/subscriptions for badge counts and full run summaries, so closed-panel progress does not rerender AppShell. |
| `lib/subagent-progress-throttler.ts` | Per-tool-call WebUI progress coalescer. Ordinary native-subagent updates are limited to one latest snapshot per 300 ms; terminal events flush pending progress first, while failure/timeout and attention/long-running control states bypass throttling. Timers are cleared with the owning RPC session. |
| `lib/agent-event-throttler.ts` | Per-session cumulative `message_update` coalescer for in-process AgentSession snapshots. Delivers the first snapshot immediately, retains only the latest pending snapshot, caps delivery to 50 ms intervals, and treats every non-update event as an ordering barrier. `message_end`, `agent_end`, `agent_settled`, and `prompt_settled` also reset the leading-edge clock for the next turn. Wrapper teardown clears its timer. (JSON/RPC 0.84+ delta-only wire events are out of scope for this coalescer; WebUI uses in-process subscribe.) |
| `lib/subagent-event-projection.ts` | Dependency-free browser projection that strips ordinary progress output and bounds progress/results/routing/control arrays and strings before SSE serialization; terminal output is capped to 8k. |
| `lib/subagent-detail-route.ts` | Pure depth/path validation for on-demand detail routes, including canonical sessions-root containment, `session.jsonl` enforcement, and symlink-escape rejection. |
| `lib/subagent-observability.ts` | Opt-in server diagnostics (`PI_WEB_SUBAGENT_OBSERVABILITY=1`) using fixed-key five-second aggregation for raw/coalesced/delivered progress, projection/handler timing, SSE count/bytes, and event-loop delay. It never retains event payloads or output. |
| `lib/subagent-observability-client.ts` | Opt-in browser diagnostics (`NEXT_PUBLIC_PI_WEB_SUBAGENT_OBSERVABILITY=1`) for SSE/handler/serialization/AppShell/SubagentPanel activity, aggregated to one console record per five seconds without retaining run output. |
| `lib/session-file-changes.ts` | Non-Git session file-change tracker: observes edit/write tool events, captures bounded target-file snapshots at event time, serializes each session's sidecar projection through a promise queue, uses asynchronous sidecar I/O with atomic rename, and serves browser-safe changed-file projections. |
| `lib/session-performance.ts` | Durable per-session performance aggregates: records ordinary Assistant call timing from raw AgentSession events (`turn_start` / first effective delta / `message_end`), persists versioned counters under `session-performance/`, projects weighted TPS + average TTFT + model breakdown, and exposes flush/delete helpers used by wrapper teardown and session DELETE. |
| `lib/task-observer-types.ts` | Desktop pet task-observer public domain contract: protocol version, size budgets, forbidden wire fields, three-axis execution/outcome/attention types, presentation/connection states, snapshot/activity/transition shapes, optional bounded active-model identity, and numeric-only Agent session resources. Intentionally omits cwd, Prompt/firstMessage fields and message records, tool args, paths, command/env, and raw errors; only Agent `title` may contain a bounded first-user preview. |
| `lib/task-observer-projection.ts` | Pure observer identity builders (`taskKey`/`activityId`/`transitionId`), safe title/progress/session-resource projection, desktop presentation priority (including Service not running / Disconnected overlays), desktop-local ack LRU helpers, bounded snapshot build/serialize (50 projects / 200 activities / 20 transitions / 8 children / 256 KiB), and content-revision fingerprinting that ignores `generatedAt`/elapsed-only changes. SDK/React/Electron free; smoke: `scripts/smoke-task-observer.ts`. |
| `lib/task-observer-agent.ts` | Ordinary Agent prompt-activity observer: prompt epoch boundaries, retry/steer retention inside the current activity, explicit session name → bounded 50-character first-user preview → content-free `Agent #XXXXXX` title precedence (including historical-session recovery), optional active-model/session-resource snapshots, safe tool/Subagent counters, blocking extension UI → `needs_input` without dialog content/options, classified `reasonCode` (no raw provider text), path-free projectKey from cwd hash, and idle-teardown eligibility independent of chat SSE listeners. ## Browser Control Contract

The bridge keeps `BROWSER_PROTOCOL_VERSION = 1` for Part 1 because the envelope and authorization model are unchanged. The extension advertises additive `extensionFeatures` during the authenticated handshake. Missing features are interpreted as an older extension: existing non-action operations remain available, while `page.act` fails before dispatch with `UNSUPPORTED_EXTENSION_CAPABILITY` until both `element_diagnostics_v1` and `post_action_state_v1` are advertised. Unknown additive response fields remain optional. A breaking envelope, identity, or authorization change still requires a protocol-version increment.

| Model tool | Extension command | Required runtime capability | Part 1 feature gate | Serialized result budget |
| --- | --- | --- | --- | --- |
| `browser_tabs` | server-local `binding.list` / `binding.set_primary` | none | none | 16 KiB |
| `browser_snapshot` | `page.snapshot` | `dom` | none | 256 KiB |
| `browser_find` | `page.find` | `dom` | none | 16 KiB |
| `browser_act` | `page.act` | `dom` | element diagnostics + post-action state | 16 KiB |
| `browser_wait` | `page.wait` | `dom` | none | 16 KiB |
| `browser_screenshot` | `page.screenshot` | `dom` | none | 360,000 base64 characters; separate image budget |
| `browser_console` | `page.console` | `debug_readonly` | none | 448 KiB |
| `browser_network` | `page.network` | `debug_readonly` | none | 448 KiB |

Interactive sessions still register all eight `browser_*` tools, but `rpc-manager` intersects the current tool preset with `filterActiveToolsForBrowserAvailability`. Unbound or disconnected sessions do not send DOM/debug tools to the model. Binding accept/revoke/debug/extension connect changes resync the live session before the next prompt.

Element refs use `el_<document-context>_<sequence>` and remain opaque to the model. Snapshot and find share the content-script document context: a later same-document snapshot does not invalidate live refs from an earlier find. Refs expire when the element disconnects or the content-script document is replaced. The extension records the issuing context per binding so a ref from an expired document returns `STALE_ELEMENT_REF`, while a ref known to another binding returns `WRONG_ELEMENT_CONTEXT`. Before policy-approved execution, the content script rejects detached, hidden, disabled, and covered targets with typed codes. Diagnostics contain only a bounded reason, redacted URL, title, document identity, and recovery guidance.

Successful actions return `completed` plus a `postAction` projection. The background service worker samples pre-action state, then performs a bounded 800 ms navigation-aware stabilization loop. It returns redacted URL, bounded title/document/context identity, ready state, safe focused role/name metadata, and explicit URL/document/focus/DOM change indicators. `stabilization: "pending"` is retained for cross-origin navigation, closure, interrupted loading, or an unstable final sample; typed/fill text is never echoed.

Part 2 adds six semantic actions behind `semantic_actions_v1`: `fill` replaces editable text, `clear` is idempotent, `press` accepts only the allowlisted key/modifier set, checkbox/radio changes are typed and idempotent, and `hover` dispatches bounded pointer events. Every mutating action remains behind the existing policy/interactability gate and error attempts are audited with redacted parameters.

Enhanced snapshots and waits are additive and capability-gated. `bounded_snapshot_v1` enables `mode: "interactive"`, `scopeElementRef` or bounded `region`, explicit truncation metadata, and `maxTextChars`. `wait_diagnostics_v1` enables `clickable`, `url_pattern` (glob semantics), `text_change`, and `document_idle`; invalid conditions/selectors fail fast, cancellation returns `WAIT_CANCELLED`, and unmet conditions return bounded `WAIT_TIMEOUT` details with compact current state.

### U1 Fixed-Fixture Baseline

The fixed one-node fixture uses compact JSON serialization (no whitespace). These measurements characterize the contract rather than set new limits: binding list 214 B, one-node snapshot 330 B, one-result find 239 B, legacy action acknowledgement 11 B, wait-timeout diagnostic 163 B, and Part 1 settled action state 404 B. The Part 1 action result remains below the 16 KiB compact budget.

| Workflow from an already bound page | U1 baseline calls | Part 1 calls | Notes |
| --- | ---: | ---: | --- |
| Find and click, then confirm state | 3 | 2 | `find -> act -> snapshot` becomes `find -> act` |
| Find and type, then confirm state | 3 | 2 | action state omits typed value |
| Click known ref and confirm navigation | 2 | 1 | post-action state reports URL/document change or pending |
| Recover post-navigation stale ref | 3 | 3 | failed act -> fresh find -> act; failure now identifies stale generation |
| Wait timeout, then inspect page | 2 | 2 | wait behavior is unchanged in Part 1 |

Redaction remains source-owned by `lib/browser-redaction.ts`, action policy remains source-owned by `lib/browser-action-policy.ts`, and extension artifacts are validated by `npm run test:browser`. Closed tabs retain at most 32 server-side tombstones; their model-safe projection is bounded and never includes raw Chrome tab ids. Reconcile carries the server-selected opaque primary binding so extension-local state does not silently override WebUI selection.

## Reuse Rules

- Do not duplicate JSONL parsing or tool-call normalization in UI code.
- If a route and a component need the same derived value, put it in `lib/` and import it from both sides.
- Keep wire types in `lib/types.ts` synchronized with route responses and hook consumers.
