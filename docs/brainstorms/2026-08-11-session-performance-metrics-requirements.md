# 单会话性能指标优化

## Problem Frame

当前聊天回复只在流式生成期间显示单条消息的即时 TPS，并以“字符数 ÷ 4 ÷ 流式时间”估算；回复结束后该值消失，无法帮助用户判断一个会话、模型或供应商的长期输出表现。

现有会话记录保存最终 token usage，但不保存模型生成耗时，因此不能准确回算历史 TPS。直接用相邻消息时间戳会混入首 token 等待、工具执行、重试和其他非生成时间，容易产生误导。

本次优化要把零散的实时速度提示升级为可信、可持久化的单会话性能摘要：保留实时反馈，从新产生的模型调用开始记录准确样本，并提供会话加权平均 TPS、平均首 token 时间（TTFT）、样本数和按模型拆分。

---

## Key Flows

- F1. 查看正在生成的回复
  - **Trigger:** 用户发送消息并开始接收模型输出。
  - **Steps:** 界面继续展示当前回复的实时速度；在最终 token usage 尚不可用时明确其为估算值；回复完成后生成一个准确性能样本。
  - **Outcome:** 用户获得即时反馈，同时完成后的会话统计不依赖字符估算。
  - **Covered by:** R1, R2, R3, R8

- F2. 查看会话性能摘要
  - **Trigger:** 用户查看当前会话顶部资源区或展开性能详情。
  - **Steps:** 界面展示会话加权平均 TPS；详情展示平均 TTFT、样本数和按模型拆分；若没有准确样本，则显示明确空状态。
  - **Outcome:** 用户可以判断当前会话的整体响应表现，并识别混合模型造成的差异。
  - **Covered by:** R4, R5, R6, R7

- F3. 重新打开或管理会话
  - **Trigger:** 用户刷新页面、重启服务、归档/恢复、分叉、切换分支或删除会话。
  - **Steps:** 同一会话恢复既有准确样本；归档不丢失统计；新分叉会话从自己的样本开始；删除会话时清理对应统计。
  - **Outcome:** 指标生命周期与现有会话语义一致，不污染会话 JSONL，也不跨会话误归属。
  - **Covered by:** R9, R10, R11

## Requirements

**指标口径**

- R1. 正在生成的回复应继续提供实时 TPS，但在最终 token usage 尚不可用时必须明确标识为估算值，不得与完成后的准确会话平均值混为同一口径。
- R2. 每次普通 Assistant 模型调用完成后，应基于该调用的最终 output token 数和实际流式输出时长形成 TPS 样本；流式输出时长从首个有效输出到该调用完成，不包含 TTFT、工具执行等待或两次模型调用之间的停顿。
- R3. 每次普通 Assistant 模型调用应记录 TTFT，定义为该次模型调用开始到首个有效输出的时间。失败、取消、无有效输出或缺失必要 usage/timing 的调用不得进入 TPS/TTFT 平均值，并不得以 0 值拉低结果。
- R4. 单会话平均 TPS 必须使用加权口径：`全部有效样本的 output token 总数 ÷ 全部有效样本的流式输出总时长`，不得使用单次 TPS 的简单算术平均。平均 TTFT按有效样本做算术平均，并同时展示样本数。
- R5. 普通 Assistant 输出是性能统计对象；工具自身执行时间、工具结果 usage、压缩、分支摘要等后台调用不纳入首版会话 TPS，以确保指标表达用户实际看到的模型回复速度。

**展示与解释**

- R6. 当前会话顶部资源区应展示会话加权平均 TPS；展开详情后应展示平均 TPS、平均 TTFT、有效样本数，以及按 provider/model 拆分的相同指标。
- R7. 当会话使用多个模型时，汇总值必须明确为混合模型会话，并提供按模型拆分，避免用户把汇总值误认为当前模型的独立表现。
- R8. 实时估算值与持久化准确值应采用清晰、可本地化、可访问的标签和说明。速度数值使用中性视觉表达，不使用缺乏统一基准的固定红/黄/绿“快慢评级”。
- R9. 旧会话或尚无有效样本的会话必须显示“暂无准确样本”及简短原因；不得根据历史相邻消息时间戳伪造回填，也不得把实时字符估算写成历史准确值。

**持久化与会话生命周期**

- R10. 准确性能样本应随单个会话持久化，并在页面刷新和服务重启后保留；性能数据不得修改 Pi 会话 JSONL 的原始格式或影响 Pi CLI 读取。
- R11. 归档/恢复会话应保留性能数据；删除会话应清理对应数据；Fork 创建的新会话不继承父会话性能样本；同一会话内的 Branch 沿用现有 lifetime 统计语义，样本仍归属于该会话。
- R12. 新统计只能从功能上线后实际观测到的调用开始积累。已有 token/cost 会话统计、上下文占用、Usage 全局统计和 Automation usage 的口径与行为不得被改变。

**质量与性能**

- R13. 指标采集不得依赖浏览器标签页是否可见、组件是否挂载或 SSE 展示节流；断开页面不应改变服务端仍在执行的调用样本结果。
- R14. 指标更新不得引入高频磁盘写入、全量会话扫描或历史消息列表的持续重渲染；长会话与流式输出性能不得因该功能明显退化。
- R15. 应覆盖指标计算、无效样本过滤、混合模型拆分、持久化恢复、会话生命周期和实时/准确口径区分的自动化验证，并保持中英文文案一致。

## Acceptance Examples

- AE1. **Covers R1, R2, R4.** Given 一条回复正在生成，when 最终 usage 尚未返回，then 界面显示“估算实时 TPS”；when 回复以 120 output tokens、4 秒有效流式时长完成，then 会话准确统计新增一个 30.0 TPS 样本。
- AE2. **Covers R4.** Given 会话有两个有效样本，分别为 100 tokens/2 秒和 100 tokens/8 秒，then 会话平均 TPS 为 20.0，而不是单次 TPS（50 和 12.5）的算术平均 31.25。
- AE3. **Covers R3, R5.** Given 一次调用等待首 token 3 秒、流式输出 5 秒，随后工具执行 20 秒，then TTFT 记录为 3 秒，TPS 分母只使用 5 秒，工具执行 20 秒不进入 TPS。
- AE4. **Covers R7.** Given 同一会话先后使用两个模型，then 顶部显示混合会话汇总值，详情分别列出两个 provider/model 的指标和样本数。
- AE5. **Covers R9, R12.** Given 用户打开功能上线前已有大量消息的旧会话，then 界面显示“暂无准确样本”，而不是根据 JSONL 消息间隔估算历史 TPS。
- AE6. **Covers R10, R11.** Given 会话已有样本，when 页面刷新、服务重启、归档并恢复该会话，then 样本仍可用；when 会话被删除，then 对应性能数据被清理。
- AE7. **Covers R11.** Given 用户 Fork 一个已有性能样本的会话，then 新会话初始显示“暂无准确样本”，父会话统计保持不变。

## Success Criteria

- 用户可以在当前会话中同时区分“当前回复的实时估算速度”和“会话历史的准确平均速度”。
- 会话平均 TPS、TTFT、样本数和按模型拆分在刷新与服务重启后保持一致。
- 混合模型、旧会话、失败/取消调用和工具执行等边界不会生成误导性数值。
- 指标采集不改变现有会话 JSONL、token/cost 统计或聊天生命周期，也不引入可感知的流式渲染退化。
- 后续实施计划无需再发明产品口径、展示层级或兼容性边界。

---

## Scope Boundaries

- 首版不回填功能上线前的历史 TPS/TTFT。
- 首版不提供趋势图、p50/p95、单次调用明细列表、跨项目排行榜或供应商基准测试。
- 首版不把固定 TPS 阈值解释为模型质量，也不提供红/黄/绿速度评级。
- 首版不改变全局 Usage 弹窗的费用/Token 聚合口径，不把性能样本混入 Automation 或 Subagent usage。
- 首版不对压缩、分支摘要、视觉回退或工具内部模型调用做 TPS 统计。

---

## Key Decisions

- 采用准确、可持久化口径：宁可旧会话没有数值，也不使用混入等待和工具时间的近似回填。
- 采用均衡诊断范围：会话平均 TPS 是主指标，TTFT、样本数和按模型拆分用于解释该数字。
- 会话平均采用 token/总流式时长的加权算法，避免短输出或极端样本扭曲简单平均。
- 实时 TPS 保留但明确标注为估算；持久化统计使用最终 output usage。
- 性能数据遵循会话生命周期，但不侵入 Pi 原始 JSONL 格式。

---

## Dependencies / Assumptions

- 模型完成事件能够提供最终 output token usage；只有同时具备有效 usage 和时间边界的调用才成为准确样本。
- 服务端 Agent 生命周期能够观察模型调用开始、首个有效输出和调用完成边界，不依赖浏览器渲染时钟。
- 一个用户 Prompt 可能触发多次 Assistant 模型调用；每次调用独立形成样本，工具执行间隔不并入任何样本。
