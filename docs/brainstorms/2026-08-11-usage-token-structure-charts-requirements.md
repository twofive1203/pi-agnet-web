# 用量统计 Token 结构图表

## Problem Frame

当前用量统计以指标卡、列表和每日费用简易横条为主，用户能看到精确值，但难以快速判断输入、输出、缓存读取、缓存写入四类 Token 的构成，以及这种构成如何随时间变化。

本次增强的核心不是建设完整成本驾驶舱，而是在现有用量弹窗中提供一张聚焦、易读、低负担的 Token 结构主图，让用户同时回答：

- 哪一类 Token 占主要部分；
- 总用量在哪些时间段发生变化；
- 构成比例是否出现明显变化。

现有统计已具备按日 Token、模型、供应商、会话、主会话/子代理等聚合数据；本需求是在既有产品形态上扩展，不新建独立分析中心。

---

## Key Flows

- F1. 查看近期 Token 结构
  - **Trigger:** 用户从当前会话资源面板打开全局用量统计。
  - **Actors:** 用量统计查看者。
  - **Steps:** 弹窗默认加载当前工作区近 7 天数据；用户查看堆叠主图；悬停、键盘聚焦或触屏点击某个时间桶；Tooltip 展示总量、四类 Token 数值与占比。
  - **Outcome:** 用户无需读取明细表即可识别主要 Token 类型和每日变化。
  - **Covered by:** R1, R2, R5, R8

- F2. 比较绝对量与结构比例
  - **Trigger:** 某些时间段总 Token 差异较大，绝对堆叠难以比较比例。
  - **Actors:** 用量统计查看者。
  - **Steps:** 用户从“总量”切换到“占比”；页面不重新请求数据；图表改为 100% 堆叠；用户通过相同 Tooltip 查看精确值和比例。
  - **Outcome:** 用户既能理解规模变化，也能识别结构变化。
  - **Covered by:** R3, R5, R13

- F3. 查看中长期趋势
  - **Trigger:** 用户选择 30 天、90 天或自定义更长日期范围。
  - **Actors:** 用量统计查看者。
  - **Steps:** 用户选择范围；系统按跨度自动采用日、周或月粒度；加载期间保留上一次成功结果并显示刷新状态；新数据返回后更新图表及明细。
  - **Outcome:** 长范围仍保持可读，不因过多数据点造成明显拥挤或卡顿。
  - **Covered by:** R1, R4, R12, R13

## Requirements

**范围与筛选**

- R1. 保留现有“全部 / 当前目录”范围和自定义起止日期，并增加近 7 天、30 天、90 天快捷范围；有活动工作区时继续默认“当前目录 + 近 7 天”。快捷范围立即加载，自定义范围只在日期完整且合法后应用，避免无效或重复请求。
- R2. 用一张全宽 Token 堆叠柱状主图替换现有每日费用横条；四个堆叠系列固定为输入、输出、缓存读取、缓存写入。总费用、主会话费用、子代理费用继续保留在顶部指标卡，不在首版保留每日费用趋势图。

**图表阅读模式**

- R3. 主图提供“总量 / 占比”双模式：总量模式显示每个时间桶的绝对 Token 堆叠和可比较的总高度；占比模式显示 100% 堆叠。切换模式不改变筛选范围，也不触发网络请求。
- R4. 时间粒度自动选择：31 天及以内按日，32–180 天按自然周，181 天以上按自然月。没有用量的时间桶必须补零并保留在时间轴中，避免把数据间断误读为连续趋势。界面应明确显示当前粒度。
- R5. 每个时间桶的 Tooltip 必须展示时间范围、总 Token，以及四类 Token 各自的精确值和占比；两种图表模式使用同一套精确值，百分比仅作辅助显示，舍入后允许存在极小合计误差。
- R6. 图例只用于定位和高亮系列，不隐藏系列、不改变分母。首版不提供跨图筛选、柱子下钻、框选、缩放或拖拽。触屏点击可固定 Tooltip，再次点击空白区域或按 Escape 解除。
- R7. 现有 Token 汇总、模型、供应商、会话排行和扫描诊断继续保留，并始终反映整个已选日期范围；主图交互不改变下方明细口径。

**可访问性与响应式**

- R8. 图表不能只依赖颜色传达含义：系列必须有明确图例和文本 Tooltip；时间桶支持键盘聚焦，左右方向键移动，Home/End 跳到首尾；焦点状态清晰并可被辅助技术识别。
- R9. 窄屏下图表不得造成页面级横向溢出，系统可减少轴标签密度但不得丢失数据桶；Tooltip 必须限制在可视区域内。触屏不得依赖 hover，`prefers-reduced-motion` 下不播放装饰性图表动画。

**数据口径**

- R10. 图表沿用当前用量统计口径：统计持久化 Assistant usage，遵循当前“是否包含归档会话”设置，包含归属于父会话的原生子代理用量；图表各时间桶之和必须与所选范围 Token 汇总一致。
- R11. 时间分桶沿用统计响应声明的时区，并在范围/粒度辅助信息中可见；首版不提供用户自选时区。模型、供应商、主会话/子代理的统计口径不得因新增主图而改变。

**性能与稳定性**

- R12. 服务端只返回图表所需的聚合时间桶，不向浏览器发送原始 usage 记录；自动粒度应控制常见范围的数据点数量，图表渲染成本随时间桶数量而非消息条数增长。
- R13. “总量 / 占比”、Tooltip、图例高亮都必须在客户端基于同一份响应完成；筛选变化应取消过期请求，加载新范围时保留上一次成功图表，失败时显示错误但不把可用旧数据清空。
- R14. 用量弹窗继续按需加载，新增图表不得增加初始聊天工作台的必要下载与渲染成本。若实现计划考虑引入图表依赖，必须先比较动态分包体积、首次打开耗时、主题适配和键盘/触屏可访问性；无明显收益时优先轻量实现。
- R15. 新增分桶和图表响应不得让现有规模基准明显回退。以仓库现有 1,000 个合成会话基准作为回归参照，Usage 聚合耗时不应比同环境修改前增加超过 20%；还需覆盖空日期、单日、跨周、跨月、全零和超长范围。

## Acceptance Examples

- AE1. **Covers R2, R3, R5, R10.** 给定近 7 天内输入 600、输出 200、缓存读取 150、缓存写入 50，打开弹窗时主图以四段堆叠展示；Tooltip 显示总计 1,000 及 60%/20%/15%/5%；切换占比模式后不发起新请求。
- AE2. **Covers R4.** 给定 90 天范围，主图按自然周展示；其中一周无任何 usage 时，该周仍显示为零值时间桶，不直接连接前后两周。
- AE3. **Covers R6, R8, R9.** 给定移动端或纯键盘操作，用户能够固定某个时间桶的 Tooltip、读取四类值，并通过 Escape 或空白区域解除；页面不产生横向溢出。
- AE4. **Covers R7, R13.** 给定用户从 7 天切换到 90 天，新请求进行中仍显示 7 天图表及加载状态；若请求失败，7 天结果继续可读并出现错误提示，下方明细不进入虚假的空数据状态。
- AE5. **Covers R10, R11.** 给定范围包含主会话、子代理和归档会话，图表总 Token 与顶部汇总严格一致，并遵循当前归档设置及响应中声明的时区。

## Success Criteria

- 目标用户能在 10 秒内从首屏判断主要 Token 类型、最高用量时段及是否存在明显构成变化。
- 用户无需在“看总规模”和“看结构比例”之间重新选择日期或等待第二次请求。
- 图表总数与既有汇总口径一致，不引入主会话、子代理、归档或时区方面的新歧义。
- 7/30/90 天和常见自定义范围在桌面、窄屏、触屏及键盘操作下均保持可读。
- 规划与实现人员无需再发明首版图表类型、模式、粒度、交互边界或性能验收口径。

---

## Scope Boundaries

- 不建设独立“用量中心”页面，继续使用现有用量弹窗。
- 不增加环形图、模型/供应商图表或多图联动仪表盘；模型、供应商和会话继续使用明细排行。
- 不提供每日费用趋势；费用只保留现有汇总卡。
- 不提供预算、告警、同比/环比、预测、导出或分享。
- 不提供图例显隐、时间桶下钻、跨图过滤、缩放、框选或拖拽。
- 不新增用户自选时区。
- 不为首版预先建设持久化 Usage 数据库、后台预聚合任务或复杂缓存层；只有基准证明现有扫描成为瓶颈时再单独规划。

---

## Key Decisions

- 主目标是分析 Token 类型构成，而非成本控制或综合经营仪表盘。
- 采用现有弹窗内的聚焦增强，而非多图仪表盘或独立页面。
- 主图采用时间序列堆叠柱状图，优先展示每日变化；环形图不进入首版。
- 同一主图提供绝对总量和 100% 占比两种阅读方式。
- 长范围自动切换日/周/月粒度，不把粒度选择负担交给用户。
- 交互保持轻量，只提供 Tooltip、键盘/触屏读取和图例高亮。
- 现有每日费用横条由 Token 主图替换，避免两个趋势图竞争注意力。
- 性能优先复用既有索引候选与服务端聚合；先守住基准，再按证据引入更重的缓存或索引方案。

---

## Dependencies / Assumptions

- 现有 `UsageStatsResult.byDay` 已包含四类 Token 和费用汇总，可作为日粒度基础；周/月粒度及空桶补齐需要在规划阶段确定由服务端统一产出还是由共享纯函数聚合。
- 当前用量弹窗已通过动态导入按需加载，因此可以保持初始聊天工作台不受图表代码影响。
- 仓库当前没有专用图表依赖；是否引入依赖是规划阶段的技术决策，不是产品要求。
- 2026-08-11 实测现有规模基准：默认 40 个合成会话时全局 Usage 约 10.1 ms；1,000 个合成会话时约 173.9 ms。该结果是本机合成数据基线，不代表所有真实环境的绝对 SLA。
