# 服务器访问认证

## Problem Frame

蜗牛派拥有项目文件读写、命令执行、Agent 调用和模型凭据管理等高权限能力，但当前没有面向整个 Web 应用的访问认证。更危险的是，官方生产运行时在未指定 hostname 时会继承 Next.js 的 `0.0.0.0` 默认值，因此用户以为是“本地启动”时，服务也可能已暴露到局域网。

目标不是增加一套完整账号系统，而是为单实例、单管理者部署建立安全默认：本地使用保持便捷，任何有意或无意的远程监听都必须经过统一访问密钥认证。

---

## Actors

- A1. 实例运维者：启动、部署、查看首次访问密钥并在必要时轮换密钥。
- A2. Web 访问者：通过浏览器输入访问密钥，获得有限期登录会话后使用蜗牛派。

---

## Key Flows

```text
官方启动入口
  ├─ 本地默认 ──> 仅监听回环地址 ──> 无需认证
  └─ --server / 非回环监听 / 部署环境配置
                  └─> 加载或首次生成访问密钥校验信息
                       └─> 全局认证门禁
                            ├─ 未登录：解锁页
                            └─ 已登录：7 天固定会话 ──> 蜗牛派
```

- F1. 本地安全启动
  - **Trigger:** A1 不带服务器参数启动官方入口。
  - **Actors:** A1
  - **Steps:** 服务仅绑定回环地址；本机浏览器直接访问；不要求输入访问密钥。
  - **Outcome:** 保持本地使用体验，同时不再默认暴露给局域网。
  - **Covered by:** R1, R2

- F2. 首次服务器启动与解锁
  - **Trigger:** A1 使用服务器模式、非回环监听或等价部署环境配置启动。
  - **Actors:** A1, A2
  - **Steps:** 服务首次生成高熵访问密钥并只展示一次；所有受保护请求先进入解锁页；A2 输入密钥；验证成功后获得 7 天固定会话。
  - **Outcome:** 未持有访问密钥的人无法读取项目内容或调用高权限能力。
  - **Covered by:** R3, R4, R5, R6, R8, R11, R12, R13

- F3. 重启与再次访问
  - **Trigger:** 服务器模式实例重启，且访问密钥未轮换。
  - **Actors:** A1, A2
  - **Steps:** 服务加载既有校验信息，不重复打印访问密钥；未过期浏览器会话继续有效；过期会话回到解锁页。
  - **Outcome:** 部署重启不会无故更换密钥或中断仍有效的登录。
  - **Covered by:** R7, R13

- F4. 密钥轮换与恢复
  - **Trigger:** A1 怀疑密钥泄露或遗失密钥。
  - **Actors:** A1, A2
  - **Steps:** A1 通过明确的运维操作生成新密钥；新密钥只展示一次；所有旧会话立即失效；A2 使用新密钥重新登录。
  - **Outcome:** 无需读取或恢复旧明文密钥即可恢复控制权。
  - **Covered by:** R10, R14

## Requirements

**安全启动语义**

- R1. `spi`、`npm run start`、PM2 等官方入口默认只能监听回环地址；未显式选择远程部署时，不得继承 `0.0.0.0` 之类的非回环默认值。
- R2. 本地默认模式保持免认证，避免给现有本机工作流增加不必要步骤。
- R3. `spi` 提供明确的 `--server` 入口；PM2、容器和其他官方部署方式提供等价的环境配置。
- R4. 任何官方入口只要请求非回环监听，就必须自动启用全局认证，不能依赖操作者同时记住 `--server`；显式 `--server` 即使绑定回环地址，也必须启用认证，以支持本机反向代理部署。
- R5. 服务器模式无法建立有效认证状态时必须拒绝启动或拒绝受保护访问，不得静默降级为无认证服务。

**访问密钥与运维**

- R6. 首次服务器模式启动自动生成不可预测的高熵访问密钥，只向运维者展示一次；持久化内容不得允许直接还原明文密钥，并应限制为当前系统用户可访问。
- R7. 后续重启复用既有访问密钥校验信息，不再次输出明文密钥，也不自动更换密钥。
- R8. 登录验证必须采用抗时序泄漏的比较方式，并对连续失败尝试实施有界限流；错误响应和日志不得泄漏密钥、会话令牌或可用于推断密钥的信息。
- R9. 明确区分“访问密钥”和“加密密钥”，用户文案、CLI 输出和文档统一使用“访问密钥”。
- R10. 提供显式密钥轮换/遗失恢复操作：生成新密钥、只展示一次，并立即使旧密钥和全部既有会话失效。

**Web 解锁与会话**

- R11. 未登录访问页面时进入专用 Web 解锁页；只有解锁流程所必需的最小页面和静态资源可匿名访问，不能泄漏项目、会话、路径、模型或配置元数据。
- R12. 全局认证必须覆盖普通页面、文件查看页、全部普通 API、Agent 命令接口和 SSE 流；不能只保护首页。未登录页面请求应进入解锁流程，未登录 API/SSE 请求应返回明确的未认证响应。
- R13. 解锁成功后建立浏览器不可读的会话。会话采用 7 天固定有效期，不因活动无限续期；服务进程重启后，在未过期且访问密钥未轮换的前提下继续有效。
- R14. 提供明确的退出登录入口；退出、会话到期或访问密钥轮换后，再次访问受保护内容必须重新输入访问密钥。
- R15. 会话应限制跨站携带；在有效 HTTPS 部署下必须启用安全传输属性。认证状态不得通过 URL 查询参数传递。

**部署边界**

- R16. 首版允许通过 HTTP 使用服务器模式，但启动输出、解锁页和部署文档必须明确警告：HTTP 不加密访问密钥或会话，不适合直接暴露到公网。
- R17. 官方文档提供通过 HTTPS 反向代理部署的推荐路径，并解释服务器模式在反向代理绑定回环地址时仍需显式启用。
- R18. 全局访问认证不改变现有更严格的本地能力边界；Automation、本机目录选择器和浏览器桥接等已有 loopback-only 能力不能因为用户已登录而自动开放给远程客户端。
- R19. 启用该能力不得修改现有项目、会话、模型或供应商凭据数据；本地默认模式升级后无需迁移账号数据。

## Acceptance Examples

- AE1. **Covers R1, R2.** Given 用户直接执行 `spi`，when 服务启动，then 只监听回环地址，且本机打开页面无需登录。
- AE2. **Covers R3, R4, R6.** Given 尚无访问密钥校验信息，when 用户执行 `spi --server` 或通过官方入口请求监听 `0.0.0.0`，then 服务启用认证、首次生成并只展示一次访问密钥，匿名用户不能进入项目。
- AE3. **Covers R4.** Given 用户通过 Nginx/Caddy 将流量代理到回环地址，when 后端以 `--server` 或等价环境配置启动，then 来自代理后的所有应用请求仍需认证。
- AE4. **Covers R11, R12.** Given 浏览器没有有效会话，when 它直接请求项目页面、文件 API、Agent API 或 SSE 地址，then 页面进入解锁流程，API/SSE 返回未认证结果，且响应不包含业务数据。
- AE5. **Covers R7, R13.** Given 浏览器会话尚未满 7 天且密钥未轮换，when 服务重启，then 服务不重新打印访问密钥，浏览器会话继续有效。
- AE6. **Covers R10, R14.** Given A1 轮换访问密钥，when 任意持有旧会话的浏览器再次请求，then 旧会话被拒绝并要求使用新密钥登录。
- AE7. **Covers R16.** Given 服务器模式通过 HTTP 提供服务，when 服务启动且用户打开解锁页，then CLI 与页面均显示可理解的明文传输风险警告，但不阻止继续使用。
- AE8. **Covers R18.** Given 远程用户已通过全局认证，when 其调用现有 loopback-only 能力，then 请求仍按原有本地访问策略被拒绝。

## Success Criteria

- 默认执行官方启动命令时，服务不再无意暴露到局域网。
- 服务器部署中，未持有访问密钥的访问者无法获得项目元数据、页面内容、API 数据或实时流。
- 首次部署无需预先配置账号系统，运维者可直接获得一次性展示的高熵访问密钥。
- 正常重启不更换密钥、不重复泄漏密钥，也不使未过期会话失效。
- 密钥泄露或遗失后，运维者可通过轮换恢复控制权并强制注销全部旧会话。
- 后续实施计划无需再发明本地/服务器模式、登录体验、会话期限、HTTP 策略或轮换行为。

---

## Scope Boundaries

- 首版是单实例、单共享访问密钥模型，不提供用户名、多用户、角色权限或项目级授权。
- 不集成 OAuth、OIDC、LDAP、TOTP、Passkey 或第三方身份平台。
- 首版不内置 TLS 证书申请、续期或 HTTPS 服务；推荐由反向代理或隧道提供 HTTPS。
- 不通过 URL 参数、启动命令明文参数或可被前端脚本读取的存储传递访问密钥。
- 不因新增全局认证而放宽现有 loopback-only 能力。
- 不承诺多个并行实例之间共享登录会话或限流状态；多实例部署需要后续单独设计。

---

## Key Decisions

- 采用应用内 Web 解锁页与会话，而不是仅依赖外部反向代理认证：确保不同官方部署入口具有一致的安全底线。
- 默认回环监听，任何非回环监听强制认证：修复当前默认 `0.0.0.0` 带来的误暴露风险，避免 `--hostname` 绕过服务器模式。
- 访问密钥首次生成后持久化不可逆校验信息：兼顾零配置首次使用、重启稳定性和明文最小化。
- 登录会话固定有效 7 天且跨重启有效：平衡高权限应用的安全性与个人服务器日常体验。
- HTTP 可继续使用但必须强警告：支持局域网/VPN 快速部署，同时明确公网安全边界。
- 反向代理认证、HTTP Basic Auth 和内置 HTTPS 均不作为首版主方案：前两者无法同时满足统一体验与会话控制，后者会显著扩大证书运维范围。

---

## Dependencies / Assumptions

- 官方部署能够持久化蜗牛派 Agent 数据目录；若容器每次启动使用临时数据目录，访问密钥和跨重启会话也会随之丢失。
- 服务器仍以单一受信任系统用户运行，该用户对项目、Agent 数据和模型凭据拥有现有权限。
- 访问密钥认证保护应用访问，但不能替代 HTTPS、主机防火墙、系统账号隔离和供应商密钥管理。
