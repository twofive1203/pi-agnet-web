# 桌宠快速会话需求与可行性结论

## Problem Frame

当前桌宠是独立启动、attach-only 的任务观察器：可以展示多项目活动并打开对应 WebUI，但不能发起普通 Agent 会话。用户希望在桌宠中选择一个已有项目，通过紧凑输入面板发送首条消息并立即启动会话，减少为了“交代一个任务”切回浏览器的成本。

代码调研确认该方向**可行（Go）**：服务端现有新会话入口已经能创建真实 Pi 会话并异步发送首条消息，桌宠也已有 loopback 连接、server-mode 访问密钥、项目分组、窄 IPC 和会话 deep link。主要工作不是 Agent 能力本身，而是为桌宠新增一个受控写入边界，并在不把它扩张成第二套 Chat 客户端的前提下处理项目目录隐私、重复提交和失败恢复。

---

## Actors

- A1. 桌宠用户：希望在当前桌面上下文中快速交代一个新任务。
- A2. 桌宠客户端：展示项目选择与首条消息输入，持有本地连接状态，但不拥有 Agent 生命周期。
- A3. 蜗牛派服务：提供项目目录映射、创建会话、发送首条消息和后续任务观察。

---

## Key Flows

- F1. 快速启动会话
  - **Trigger:** A1 在桌宠或 Activity tray 点击“快速会话”。
  - **Actors:** A1, A2, A3
  - **Steps:** A2 打开紧凑输入面板并加载可用项目；A1 选择项目、输入首条文字消息并提交；A3 校验项目和请求，创建且启动一个真实会话；A2 显示启动成功，并允许打开该会话；后续运行状态进入现有 Activity tray。
  - **Outcome:** A1 不打开浏览器即可交代一个新任务，且只产生一个会话。
  - **Covered by:** R1–R7, R12

- F2. 启动失败与恢复
  - **Trigger:** 服务未连接、访问密钥无效、项目失效、模型配置不可用或网络响应不确定。
  - **Actors:** A1, A2, A3
  - **Steps:** A2 阻止或终止提交，保留未发送文字和项目选择，显示结构化原因；可恢复错误提供重试，配置类错误提供打开 WebUI 的入口；不确定结果不得盲目再次创建会话。
  - **Outcome:** 用户不会丢失草稿，也不会因重试意外创建多个会话。
  - **Covered by:** R4, R8–R10

- F3. 转入完整会话
  - **Trigger:** 会话已成功启动，A1 需要查看回复或继续交流。
  - **Actors:** A1, A2
  - **Steps:** A1 点击“打开会话”；A2 通过既有 allowlist deep link 在默认浏览器打开对应 WebUI。
  - **Outcome:** 桌宠保持轻量，完整交互继续由 WebUI 承担。
  - **Covered by:** R12, Scope Boundaries

---

## Requirements

**入口与快速输入**

- R1. 桌宠必须提供可发现的“快速会话”入口；入口仅在兼容服务已连接且具备控制权限时可提交，打开动作必须来自用户手势，不能由状态更新主动抢焦点。
- R2. 快速会话面板必须提供项目选择、项目搜索、首条文字输入、取消和启动动作；最近使用项目优先，默认选中最近项目但必须清晰可见。
- R3. 首版项目范围限定为服务当前可确认的已有项目（至少覆盖含活跃或归档会话的项目）；不要求在桌宠内新增任意目录。
- R4. 空白消息不可提交；消息长度必须有明确上限和剩余/超限反馈；提交期间禁用重复操作。
- R5. 首版必须使用该项目的默认模型、默认思考等级和标准工具配置，不在桌宠中增加模型、思考或工具选择器。
- R6. 一次确认必须至多创建一个会话。客户端重试、双击、超时后重连等路径必须具备幂等或等价的重复抑制语义。
- R7. 创建成功后必须返回真实 session id；面板显示“已启动”，清理已发送草稿，并由现有桌宠观察流展示后续 Running / Needs input / Ready / Blocked 状态。

**安全与隐私边界**

- R8. 会话创建必须走独立、受控的桌面写入能力；短时控制凭证和 server-mode 访问密钥只保留在 Electron main，不得进入 renderer。现有只读 observer token 不得被静默升级为通用写权限。
- R9. Renderer 只能提交有界的项目引用和用户本次输入的文字，不得提交 raw cwd；服务端必须把项目引用重新解析为当前有效、已知且存在的规范目录，并拒绝失效、冲突或越界引用。
- R10. 用户输入只允许在输入面板、Electron main 转发和服务端本次创建请求中短暂存在；不得写入桌宠设置、日志、通知、observer snapshot 或项目列表缓存。服务端正常创建的会话记录不受此限制。
- R11. 项目列表不得向 renderer 下发完整 cwd、历史 firstMessage 或会话正文。重名项目必须使用隐私安全的辅助标识进行区分，而不是直接放宽为完整路径展示。

**恢复与完整交互**

- R12. 创建成功后必须提供既有 allowlist 会话 deep link；桌宠不显示流式回复、不承载连续追问，用户需要完整交互时进入 WebUI。
- R13. 服务未运行、正在重连、访问密钥无效、项目目录已删除、项目引用过期、会话初始化失败和默认模型不可用必须使用可区分的错误状态；除已确认成功外，失败都保留本地草稿，直到用户取消或再次成功提交。

## Acceptance Examples

- AE1. **Covers R1–R7.** Given 桌宠已连接且项目 Alpha 可用，when 用户选择 Alpha、输入“检查当前测试失败原因”并点击启动，then 服务只创建一个真实会话，桌宠显示已启动，该活动随后出现在 Alpha 的 Running 列表中。
- AE2. **Covers R6, R13.** Given 启动请求发送后响应超时，when 用户点击重试，then 系统通过同一请求身份返回原会话结果或明确可重试状态，不创建第二个会话，输入文字仍保留。
- AE3. **Covers R8–R11.** Given renderer 检查项目列表和提交载荷，then 只能看到项目显示名、隐私安全引用和用户本次输入，不包含 observer/control token、访问密钥、raw cwd、历史 Prompt 或 firstMessage。
- AE4. **Covers R9, R13.** Given 项目在列表加载后被删除，when 用户提交快速会话，then 服务拒绝创建并提示“项目已不可用”，草稿保留，且不会在其他目录启动会话。
- AE5. **Covers R5, R12.** Given 会话已启动，when 用户想更换模型或继续追问，then 桌宠提供“打开会话”，而不是在小窗中复制模型选择器或流式 Chat UI。

## Success Criteria

- 用户可以通过“选择项目 → 输入一句任务 → 启动”在数秒内创建会话，无需先打开浏览器。
- 快速启动与浏览器创建的会话使用同一服务端生命周期，并能立即被现有桌宠观察。
- 失败和重试不会丢失草稿或重复创建会话。
- 新能力不向 renderer 暴露 cwd、历史会话内容或任何服务凭证，也不把桌宠变成第二套完整 WebUI。
- 后续实施规划无需再决定是否支持连续对话、模型选择或任意目录添加。

---

## Scope Boundaries

- 首版只发送首条**文字**消息；不支持连续追问、流式回复、历史消息、图片、附件或 `@` 文件引用。
- 不在桌宠中提供模型、思考等级、工具预设、系统 Prompt 或高级会话配置。
- 不在桌宠中新增项目、浏览目录、创建 WorkTree 或管理归档；项目目录管理继续留在 WebUI。
- 不提供停止任务、批准权限、响应任意 extension UI、执行 Quick Command 或修改已有会话的能力。
- 不自动启动、停止或管理 `spi` 服务；未连接时继续使用现有启动说明和重试路径。
- 不把完整 cwd 或历史 Prompt 放入 observer snapshot、renderer view、通知或桌宠设置。
- 不建设桌宠内完整 Chat 客户端；后续查看与交流始终回到 WebUI。

---

## Key Decisions

- **直接在桌宠启动，而不是只跳转 WebUI：** 这是本功能减少上下文切换的核心价值。
- **仅负责首条消息：** 启动后复用现有观察流和浏览器 deep link，避免复制 Chat、SSE、附件和扩展交互。
- **使用项目默认配置：** 保持小窗为高频快速入口，而不是缩小版会话设置页。
- **建立窄控制边界：** 会话创建是明确写操作，不能把现有只读 observer token 直接升级为写 token；控制凭证只在 main 中持有。
- **项目引用替代 raw cwd：** 服务端拥有项目目录映射和最终校验，renderer 只处理安全显示信息。
- **优先复用现有 Activity tray 体验：** 快速输入应表现为与桌宠相连的紧凑面板；是否使用同一窗口内覆盖层或独立受限子窗口可在规划阶段按焦点与多屏行为确定。

## Dependencies / Assumptions

- `app/api/agent/new/route.ts` 已具备“创建真实会话 + 异步发送首条消息”的核心能力，但当前入口接收 raw cwd，且面向已认证 WebUI；实施时需要抽取可复用的会话启动服务，而不是让桌宠绕过安全边界直接复用浏览器请求。
- 当前项目列表主要由活跃/归档 session 的 cwd 推导，并不是独立的持久项目注册表。因此首版能可靠覆盖“已有会话的项目”，但不能承诺覆盖从未创建过会话且服务重启后未重新选择的目录。
- 桌宠已有访问密钥安全存储、loopback 连接、严格 CSP、sandbox/contextIsolation、窄 preload IPC 和 Agent session deep link，可作为新能力的安全底座。
- 仓库已有拟议中的 `/api/desktop-control/**` 方向，但尚无运行时代码；快速会话可以成为该窄控制基础的首个落地能力，不能把拟议设计当成已实现依赖。
